# Branded HTML email

Admin > Messages (A22) retains the existing audience and message form and adds an Email design selector: Announcement, Service update, or Promotion. Enter plain text, select workers, customers or both, enable Also send by email, then Preview message. A branded HTML preview opens before publication. Editing any message value or design requires a fresh preview. Send reviewed message publishes application inbox messages; The notification worker automatically sends queued email batches when SMTP is configured; Deliver next email batch remains available for a manual batch of up to five. Recipients are sent individual messages, never shared CC/BCC lists. The selected template is frozen in the reviewed broadcast and survives restarts.

Design uses the store's green palette, a wordmark header, clear title and message typography, a restrained footer and mobile-friendly table layout with inline styling. No external fonts, image trackers or remote logo downloads are required. Text is escaped, not treated as arbitrary HTML. Email always includes plain text. Existing plain-text callers, including test-payment receipts, receive a branded HTML fallback automatically through the SMTP mailer.

Automatic account email covers registration email verification and resend, administrator invitations, password reset links, welcome confirmation after successful verification/invitation, and security alerts after successful password changes or resets. Buttons use the configured application origin and original secure token flows. Tokens remain single-use and expire after 30 minutes; passwords and authenticator codes are never emailed. Notification failure does not undo a completed account update and is audited without logging message contents.

SMTP must be configured in the deployment environment; OpenAI is not required for these deterministic templates. Set EMAIL_PROVIDER=smtp, SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, EMAIL_FROM, and optional SUPPORT_EMAIL as documented in .env.example. Restart the server after changing environment settings. Configure the email provider's domain verification, SPF, DKIM and DMARC in your DNS using that provider's values. Templates do not guarantee inbox delivery or replace provider setup.

Review all designs locally in work/Email-Template-Preview.html. Automated tests use a fake mailer only. Real inbox rendering, SMTP deliverability and domain authentication still need acceptance checks with your provider. Changes are local until deployed to Contabo.
